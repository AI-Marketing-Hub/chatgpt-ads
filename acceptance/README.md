# Acceptance evidence

The [v0.3.0 status](v030/status.json) and [fresh advisory probe assessment](v030/probe-assessment.json) distinguish implementation, simulated behavior and missing native evidence.

The [workflow cases](workflows/README.md) and [measurement cases](measurement/README.md) use synthetic inputs. They do not certify actual account setup, campaign delivery, tracking receipt or performance. Historical v0.2.1 review and raw runtime traces are preserved in the canonical workspace and the prior release, not promoted as acceptance of changed code.

External account feedback is a lead for verification. Public knowledge contains scoped official-source claims; private account observations and full session transcripts are excluded. A country-availability screen from one session does not diagnose another account.

Native CSV/API/measurement and live action gates remain open. See [handoff](../docs/LIVE_ACCEPTANCE.md). Windows guarded operations are deliberately unavailable until a supported backend and native evidence exist.
